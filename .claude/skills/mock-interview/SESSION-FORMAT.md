# Session Record Format

Each mock-interview session is saved to
`interview_prep/mock_practice/YYYY-MM-DD_session_N.md` (increment `N` for multiple sessions
in one day). Keep it concise — this is a working record the next session reads, not a
transcript. Follow the template below.

```markdown
---
type: Interview Prep
title: "Mock Interview — YYYY-MM-DD Session N"
description: "Hiring-manager mock interview practice session: themes, scores, weak areas, and proposed MEMORY.md edits."
tags: [interview-prep, mock-interview, YYYY-MM-DD]
timestamp: YYYY-MM-DDT00:00:00Z
---
# Mock Interview — YYYY-MM-DD (Session N)

**Focus:** [theme argument if any, else "mixed"]  •  **Questions asked:** [n]

## Themes covered
- [theme] — [one-line question paraphrase]
- ...

## Answer notes
Brief, paraphrased — not verbatim. One block per question.
- **[Theme / question]:** [what the user said, key facts used, what the follow-up exposed]

## Rubric scores (1–5)
| Dimension | Score | Note |
|-----------|-------|------|
| Structure (STAR) | | |
| Specificity & metrics | | |
| Relevance | | |
| Ownership / leadership | | |
| Conciseness | | |

## Strengths
- ...

## Weak areas to target next session
- ...

## Model rephrasings
For the 1–2 weakest answers — a tighter version in the user's voice, real facts only.
- **[Question]:** "[model answer]"

## MEMORY.md edits
- **Applied:** [what was changed in reference/MEMORY.md this session, or "none"]
- **Deferred:** [proposed edits the user didn't take yet — revisit next session, or "none"]
```

## Notes
- **Applied vs. deferred** is the important part for continuity: the next session reads the
  latest record, re-offers deferred edits, and drills the weak areas.
- Keep paraphrases honest — capture what the user actually said, including where they were vague, so
  progress across sessions is real and measurable.
